# Architecture decision records

Each record explains one architecture decision: the context that forced it, the decision,
the alternatives rejected and the consequences. See AGENTS.md for when to write one.
Records are never rewritten; a changed decision gets a new record that supersedes the old.

| Record | Decision |
|---|---|
| [0001](0001-two-processes-joined-by-a-unix-socket.md) | Foxleash runs as two processes, `foxleash mcp` and `foxleash host`, joined by a Unix socket in a 0700 directory, and its three parts check a shared protocol version on connect. |
| [0002](0002-safeguards-live-in-foxleash-not-the-mcp-client.md) | Threat model: the safeguards against prompt injection (such as per-site approval that only a user click grants, a default blocklist, allowed upload folders, untrusted page content) live in Foxleash, not in the MCP client. |
| [0003](0003-e2e-tests-in-real-firefox-over-webdriver-bidi.md) | End-to-end tests start a pinned, headless Firefox, install the extension over WebDriver BiDi and call the real tools as an MCP client; no Playwright. |
| [0004](0004-no-javascript-tool-in-v1.md) | In v1 no tool or tool parameter evaluates code strings in pages, and the extension does not request `userScripts`: every page action ships in the extension package. |
| [0005](0005-mcp-is-the-model-boundary.md) | v1 contains no LLM, model API calls or API keys: the model lives in the MCP client, and tool names and descriptions are written for any client. |
| [0006](0006-no-firefox-for-android-key-in-the-manifest.md) | The manifest has no `gecko_android` key, so AMO never marks Foxleash compatible with Firefox for Android; the extension build allows the one linter warning this causes and fails on any other. Its minimum version of 140 and that allowance are superseded by [0034](0034-firefox-142-is-the-minimum-version.md). |
| [0007](0007-per-site-approval-and-tab-redaction.md) | A site is an http(s) URL's origin; a session acts only on sites the user approved with a trusted click (stored one `storage.local` key per site, or for the session), the gate runs before the request, and tabs on other sites reach the agent redacted to their site with no title. |
| [0008](0008-e2e-tests-act-in-extension-pages-through-bidi-and-marionette.md) | The end-to-end Firefox starts with Marionette and system access: BiDi installs, navigates and evaluates in extension pages, Marionette clicks with trusted input, and tests seed settings only through the settings page. |
| [0009](0009-content-scripts-injected-per-tab.md) | Foxleash's content script is injected per tab and per request into the top frame after the site gate, never registered by URL; it only answers the background, checks its site again and hands out per-document element refs; tool results frame page content with a random id. |
| [0010](0010-page-tools-withhold-credential-field-values.md) | Page tools never return the value of a password field, a field read_page saw as one, or a field whose `autocomplete` names a password, one-time code or card number: its line shows `protected` and `filled`, and names never include a form control's value. |
| [0011](0011-screenshots-saved-by-the-mcp-server-in-its-working-folder.md) | `screenshot` captures with `tabs.captureTab(tabId)` at scale 1, never `captureVisibleTab`, gated before and after the capture; an element is its box after `scrollIntoView`, cut to the viewport; saving is done by the MCP server, as new 0600 `.png` files inside its starting folder and never through a name starting with a dot, not with `browser.downloads`. |
| [0012](0012-upload-path-policy.md) | `upload_file` reads only from the upload folders (the starting folder and `~/Downloads` unless either covers home or lies in a dot folder, or `FOXLEASH_UPLOAD_DIRS`), never through a name below the folder starting with a dot or a key-shaped name, checked again on the open descriptor's real path; bytes travel in 512 KiB chunks staged per session in the background, and a drop follows only a canceled `dragover`. |
| [0013](0013-screenshots-hide-credential-field-text.md) | Every screenshot hides the text of password fields and of fields whose `autocomplete` names a password, one-time code or card number with a user-origin sheet inserted into each frame by its own `frameIds` target, plus every top-document input once a remembered password field was revealed; a frame refusing the sheet, a frame load or a reveal during the capture refuses the screenshot, and removal is started, not awaited. |
| [0014](0014-act-tools-synthesize-pointer-input-in-the-page.md) | `click`, `hover`, `scroll` and `drag` send full synthetic pointer and mouse sequences (`pointerId` 0) from the content script at the centre of an element's visible part, refuse covered elements and frames, refuse clicks whose link, form or label leads to another site, scroll by trying the boxes a wheel would scroll, and emulate HTML drag and drop for draggable elements. |
| [0015](0015-console-recorder-in-the-page-world.md) | `read_console` records in the page's main world: a self-contained recorder injected at the top-frame commit after the page tools' gate on the committed URL, records kept in the document (300 messages of at most 1,000 characters) and read through a synchronous event round trip with a JSON string, returned only while the tab's recording has been live since that commit, and filtered by level and pattern in the MCP server. |
| [0016](0016-read-network-records-live-documents-with-non-blocking-web-request.md) | `read_network` records with six non-blocking `webRequest` listeners, per tab and top-frame document, only while that document is live (ADR 0015's rules, now in `live-documents.ts`, one instance per recorder), starting with the page's own request and keeping only requests whose top-level document is on the page's site; the Cookie, Set-Cookie, Authorization and Proxy-Authorization values are redacted at record time, the log holds the newest 500 requests within 4,000,000 characters, no bodies, and the pattern is a plain substring. |
| [0017](0017-text-input-and-keys-without-key-event-defaults.md) | `type` inserts with `execCommand("insertText")`, reads the value or text back and falls back once to the native value setter or to `beforeinput` plus DOM insertion, reporting `sent_unconfirmed` for an editor it cannot read; `press_key` sends keydown, keypress and keyup without legacy key codes and performs Enter, Tab, Escape and the select arrows itself, refusing Enter that leads to another site after the page's key listeners ran, and reads forms only through prototypes. |
| [0018](0018-click-and-enter-refuse-destinations-outside-the-web.md) | The cross-site check of `click` and `press_key` Enter refuses every destination outside the page's site: other web sites, `blob:` of another origin and any other scheme but `javascript:` (such as `mailto:`), naming only the scheme. |
| [0019](0019-download-fetches-in-the-background-and-saves-through-downloads.md) | `download` fetches the file in the background page with the user's cookies, checks the site gate on the start URL, on the final URL before reading the body and again before saving, and saves the bytes through `downloads.download` of a blob URL into Firefox's download folder under a plain name (`uniquify`, at most 100 MiB, one download at a time); it never asks. |
| [0020](0020-screenshots-pass-over-frames-showing-an-error-page.md) | A screenshot passes over a subframe that refuses the sheet only when Firefox's `onDOMContentLoaded` reported that frame's current document, by the `documentId` and url `getAllFrames` lists, as its `about:neterror?` error page for that url; the top frame and every other refusal still refuse. |
| [0021](0021-autofilled-fields-are-protected.md) | An `input` or `textarea` that matches `:autofill` when it is read is protected as in 0010, the screenshot field mask also selects `input:autofill` and `textarea:autofill`, `type` refuses such a field with `not_editable`, and `navigate` reloads with `bypassCache`, so a reload brings back no field value without Firefox's autofill mark. |
| [0022](0022-page-requests-remember-password-fields.md) | Every page request through the content script first remembers the document's password fields, through a `before` hook that `handlePageMessage` runs synchronously right before each handler and that fails the request when it throws, so a field the agent's click or the page turns into text after any earlier request stays protected. |
| [0023](0023-fill-form-sets-each-field-by-its-kind.md) | `fill_form` fills fields in request order with one result each, never stopping at a failure: text replaces the content through `type`'s path and refusal, is refused when the browser would sanitize it, and is committed by blur with one change event; selects match value then label; checkboxes and radio buttons are clicked with `element.click()`; no result depends on what a text field held; no field starts after 4 s. |
| [0024](0024-batch-runs-each-step-as-its-own-tool-call.md) | `batch` runs on the MCP server: each step goes through its tool's own input shape, callback and bridge requests, so the extension checks each one on its own; it stops at the first failure (a `fill_form` field not filled counts) and on cancellation, returns each step's content unchanged under Foxleash's headers, and caps the result item by item. |
| [0025](0025-history-loads-and-autofilled-fields.md) | After `navigate` goes back or forward, it reloads the tab with `bypassCache` when the step's load completed, the last `main_frame` request that started by the tab's last top-level commit is for that commit's URL, matched by start time and waited for up to a second since Firefox can report it after the commit, that request and every frame request started from it on or reported after it were GETs, and the tab is still in the session's group, off its prompt and on a site the session may act on; POST pages, frame-only steps, the page's own history steps and restored tabs are accepted. |
| [0026](0026-wait-for-refuses-selectors-on-attributes-that-mirror-field-values.md) | `wait_for` refuses a selector that contains `[` together with `value` or `ng-reflect`, after decoding CSS escapes and folding ASCII case, before it asks the page, so no attribute selector can test a field value that the page mirrors into `value` or an Angular development build copies into `ng-reflect-*` attributes. |
| [0027](0027-tabs-opened-from-a-session-tab.md) | Foxleash neither tracks nor groups tabs that a session's page opens: with Firefox's pop-up blocker a synthetic click or Enter on a same-site link or form that opens a new tab opens nothing, and where Firefox lets it open, a new tab joins the opener's group while a new window stays outside it; the `click` and `press_key` descriptions say so, and the end-to-end profile keeps the pop-up blocker on. |
| [0028](0028-type-adds-text-at-the-caret-of-an-editable-area.md) | In an editable area `type` adds the text at the caret when, once the element has focus, the selection lies inside it in an editable place (a selection collapsed to its end), else at the element's start, where Firefox puts the caret when it focuses an editing host; the `beforeinput` fallback follows the same rule; text fields still get the text at the end. |
| [0029](0029-tab-open-loads-a-page-in-a-tab-created-unloaded-on-it.md) | `tab_open` with a URL on a site the session may act on creates the tab with `discarded: true` and `active: false` on that URL, puts it in the session's group, loads the page in it with `tabs.update` and `loadReplace`, then selects it, and closes it when grouping fails, so the page loads only in the group, from the server as any load does rather than as a history load from the cache, and Firefox's unload and restore leave no `about:blank` entry after it; `tab_open` without a URL and a prompt's tab still start on `about:blank`. |
| [0030](0030-approval-prompt-tab-created-unloaded-on-the-prompt.md) | `tab_open` on a site that needs approval creates the tab with `discarded: true` and `active: false` on a new prompt URL, puts it in the session's group, and `ask` loads the prompt there with `tabs.update` and `loadReplace`, so Firefox's unload and restore leave no `about:blank` entry after the page; the tab is removed when grouping fails or `ask` shows nothing, and a site allowed meanwhile loads its page into the unloaded tab; `tab_open` without a URL followed by `navigate` keeps the entry, a Firefox limitation. |
| [0031](0031-screenshots-hide-every-frame-beside-another-add-ons-frame.md) | When a screenshot's `getAllFrames` listing holds another add-on's frame (a `moz-extension:` URL on another host than Foxleash's), the parent of the top-most such frame on each frame's `parentFrameId` walk takes a user sheet hiding every `iframe`, `frame`, `object`, `embed`, `browser` and `editor` with `visibility: hidden`, `opacity: 0` and `transition: none`, all `!important`; a rejected field mask of a frame that is, or lies inside, such a frame is passed over, a rejected hiding sheet or a broken or circular walk refuses, and a listing without such a frame is captured as before. |
| [0032](0032-html-drag-sends-the-ends-events-in-a-later-task.md) | An HTML `drag` sends dragstart and pointercancel, waits 20 ms so the page can start the drag in a later task, as SortableJS does, then sends drag on the start element, dragenter and dragover on the end element located before any event, at the end point moved as far as that element moved, and drop or dragleave, then dragend, with no events at points along the way; the pointer fallback is unchanged and the description tells the agent to read the page after a drop. |
| [0033](0033-session-restore-and-autofilled-fields.md) | A login field in a tab Firefox restores after a restart comes back without Firefox's autofill mark when no saved login fills it again, so `read_page` shows its value; this is accepted as measured, nothing in the extension changes, and an end-to-end test that quits and restarts Firefox on the same profile keeps checking it with the login kept and removed. |
| [0034](0034-firefox-142-is-the-minimum-version.md) | Foxleash requires Firefox 142 or later (`gecko.strict_min_version` `142.0`, esbuild target `firefox142`), the lowest version whose Firefox for Android check passes without a `gecko_android` key, so the extension build fails on every web-ext lint error and warning. |
| [0035](0035-recipes-saved-and-run-only-by-a-user-click.md) | A recipe is text (name, description, sites, steps) stored as one `recipe:<name>` key, written only by a trusted click on an extension page and never by anything arriving over MCP or native messaging; running one grants its sites for the session only, never always; `checkRecipe` refuses invisible and bidi characters and keeps joiners and variation selectors only where emoji and scripts need them; an agent gets recipes as the user's own text, and no data collection category is added. |
| [0036](0036-the-propose-page-shows-the-whole-steps.md) | On the propose page the sites and steps fields grow to their text with no scroll of their own and wrap runs of spaces and tabs, refitting after a fill, on input and when the steps label's box changes; a Save click while any of their text is out of view refits, saves nothing and re-arms; `checkRecipe` folds three or more line breaks in the steps to two. |
| [0037](0037-the-propose-page-shows-the-whole-name-and-description.md) | On the propose page the name and description are one-row textareas that wrap and grow to their text like the sites and steps, and a Save click checks all four fields; Enter adds nothing to them and a line break pasted into them becomes a space. |
| [0038](0038-agents-sharing-a-session-share-its-tab-group.md) | Agents that share one MCP connection are one session and share its tab group and site approvals; Foxleash adds no per-agent tab ownership; the server instructions tell each agent to keep to the tabs it opened, its own actions opened or the user pointed it to, and the `tabs_list` description says other agents' tabs appear too. |
| [0039](0039-tools-declare-their-result-size-for-claude-code.md) | `read_page` (101,000), `get_page_text` (401,000) and `batch` (500,000, the ceiling) declare `_meta["anthropic/maxResultSizeChars"]`, each value sized from the tool's own cap, so Claude Code keeps their results inline instead of saving them to a file; `read_network`, `read_console` and every other tool do not declare it. |
| [0040](0040-page-requests-wait-for-a-navigation-under-way.md) | Page requests and `screenshot` wait up to 10 s for a top-frame navigation under way in a tab of the session's group, tracked per tab from `onBeforeNavigate`, `onCommitted`, `onDOMContentLoaded`, `onCompleted` and status `complete` (not `onErrorOccurred`), fail `page_loading` when it has not committed by then, treat a swap's about:blank as loading, and run a request that is not an act once more when a navigation began during it; an act is never sent twice, the site gate is unchanged, and a request answers within 50 s. |
| [0041](0041-the-project-is-named-foxleash.md) | The project is named Foxleash in every identifier (extension name and add-on id `foxleash@mattiasw.com`, native host, launcher and cache paths, MCP server name, environment variables, packages, release file names), with the former name kept only in this record and its changelog entry; earlier records were changed only by substituting the name. |
| [0042](0042-page-waits-count-time-across-message-channel-turns.md) | The page code's settle waits (`SETTLE_MS` 100 ms, `DRAG_START_MS` 20 ms) count time across `MessageChannel` turns, not with a timer, so Firefox's one-second timer delay in a tab that is not the active one does not stretch them; an HTML drag also waits one content-script timer turn, so a page that starts its drag in a 0 ms timer starts it first. |
| [0043](0043-read-page-finds-lines-by-the-text-it-shows.md) | `read_page` with `find` (and optionally `role`) returns the first 20 lines whose name, unprotected field value, text or link address contains the text, ignoring case, compared in the form the tree shows it (whitespace collapsed, cut at 200 characters, unescaped), each after its ancestor lines, with counts checked by `foundLinesOf` and notes of numbers only; role, state words and references never match; the walk goes to the end of the page; `PROTOCOL_VERSION` is 3. |
