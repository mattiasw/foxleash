## Name

Foxleash

## Summary

Lets an AI agent on your computer use your own Firefox through MCP tools: it opens tabs, and reads pages, clicks, types and fills in forms on the sites you approve.

## Description

Foxleash lets an AI agent on your own computer, such as Claude Code or any other MCP client, use your own Firefox through MCP tools, in your normal Firefox profile with your logins. Foxleash contains no AI model: it makes no model API calls and holds no API keys.

Foxleash has three parts:

- this extension, which carries out the actions,
- a native host that Firefox starts and that the extension talks to,
- an MCP server that your AI agent starts and that talks to the native host.

The native host and the MCP server are one program that runs on your computer and that you install separately. It needs Node.js 24 or later, and the project's README explains how to install it. The extension does nothing without it. When you install the extension, it opens a page that shows the command that installs the program and whether the program is connected, and the extension's settings show the same. The first-run page and the settings also say when the program is too old for the extension, or newer than it, and show the command that updates the part that is behind.

The agent can:

- open tabs and navigate them,
- read pages,
- click, type and fill in forms, and learn from each action's result what changed in the page: the results of actions, and of opening, navigating and waiting in a tab, also carry a view of the page (the page itself the first time, then only what changed), read like any page and only on sites you approved,
- take screenshots,
- read the console and network activity,
- upload files from allowed folders,
- propose recipes, written steps for a task across sites, which you read, edit and save or discard in Firefox, and read the recipes you saved, and ask you to allow a saved recipe's sites for a session in one click,
- ask you on one page to allow the sites a task needs for a session in one click,
- download files from sites you approved into your Firefox download folder.

Each agent session works in its own orange tab group titled Foxleash, and Foxleash acts only on tabs in that group, including tabs you move into it and tabs that a page in the group opens, also after your own click. When the agent session ends, Foxleash closes its group if the group holds only blank tabs, so pages you may still be reading stay open. While Foxleash is asking you something in a tab, the agent cannot select another tab of its group, and Foxleash does not select the tabs it opens for the agent meanwhile. Firefox itself may still select a tab to show a page's sign-in dialog or to ask whether you want to leave a page, and a page may select a tab it opens, also after the agent's click. With the "Open each agent session in its own window" setting on, each session's tabs open in a new window of their own. Firefox may bring that window to the front when it opens it, and a page in it that asks you something (whether to allow a site, to save or run a recipe, or to allow the sites a task needs) brings that window to the front if your desktop allows it. Foxleash closes the blank tab that window opens with once another tab in it is selected, closes the window at once if the session's first tab cannot be opened, and closes it when the session ends if it holds only blank tabs and is not your last window. The Foxleash button in the toolbar shows ON on the tabs an agent session can use, and ! on tabs outside an agent session's group when the program is too old for the extension or newer than it, and clicking it opens Foxleash's settings.

Foxleash acts in your logged-in browser. The main risk is prompt injection: a web page can contain instructions aimed at the AI model, such as an instruction to send the contents of the page somewhere. Models can be fooled by these, and no defense is complete. Foxleash limits what a fooled agent can do:

- It reads and acts in a tab's page only while that page is on a site you approved in the browser. Content that page embeds from other sites, blocklisted ones included, can show up in what the agent reads, for example in a screenshot. Before the agent opens a page on a site you have not approved, Foxleash asks you in that tab whether to allow it: for this session, always, or not at all. The approval can only come from your click; nothing the agent sends can grant it. The sites you allowed always are listed in the extension's settings, where you can revoke them. The settings also list each running agent session, with the sites you allowed or refused for it and the prompts you closed without an answer, where you can forget each of those answers.
- The settings list each running agent session with a Stop this session button: after your click Foxleash refuses every tool call of that session, also on sites you allowed always, and asks you nothing more for it. Its tabs stay open. Nothing the agent sends can undo the stop, which lasts until Firefox restarts or Foxleash is updated; a new agent session is not stopped, and an agent that can also run programs on your computer can start one itself.
- A built-in list of common financial and health sites is blocked by default: when the agent asks to open one of them or to reload a tab that shows one, Foxleash refuses before anything is loaded, and it does not read or act in a tab's page while it shows one of them. Such a tab reaches the agent only as its site's address, even if you approved the site. You can edit the list in the extension's settings. The list is short and names mostly sites in the United States, the Nordic countries and the United Kingdom. It cannot name every such site: a site that is not on it is not blocked until you add it.
- File uploads only read from allowed folders (the agent's working folder and your desktop's download folder, such as ~/Downloads, by default), and refuse dotfiles, files named like keys, files that hold a PEM, OpenSSH, PuTTY, PGP or age private key, and files saved or changed in the last 5 seconds.
- Downloads save only a file served by a site you approved, after any redirects, and only into your Firefox download folder under a plain file name, never over an existing file. The file is saved as the site sent it, with nothing hidden or redacted: it can hold the value of a protected field that the site put in a page, and sign-in tokens.
- In the tabs of an agent's tab group, Foxleash stops a page or frame load whose answer comes from a site you have not approved, or that is on the blocklist, and is anything other than a web page: a file Firefox would save, or a PDF, image or text it would show. Nothing of it is saved or shown. Without this, a page on a site you approved could get such a file saved into your download folder, from where an upload by the agent could hand it to that page. The result of an agent's action lists the site when the load was stopped during the action or the wait that follows it, in the tab, in a tab the action opened or in a window opened from the tab, and when the agent opens or navigates a tab whose own load is stopped, the call fails at once, saying that a file was stopped and that the site must be approved first. The request still reaches that site, with the cookies Firefox sends for it. A window that a page in the group opens, or that you open from one of its tabs, is covered too until it closes, though the agent cannot reach it, unless the tab that opened it closes at once; a window you open may not be covered for the first address it loads. When such a site's own service worker gives the answer, Firefox starts saving the file, and Foxleash then cancels that download and removes its file, after the fact: the file exists for a moment, during which the agent's uploads refuse it as a file saved in the last 5 seconds. A Blob file that a page of such a site builds itself in those tabs is cancelled and removed the same way. That can also cancel and remove a download of your own: one of exactly the address of a load begun in the agent's tabs in the 10 minutes before, on a site the session may not act on, that got no answer from the network; while a page in those tabs keeps more than 200 loads waiting, every download from a site that session may not act on, in any tab, until 10 minutes after the last of them; a Blob file from a site that a tab of the agent's group shows in any frame, or showed in the last 60 seconds; a Blob file that a sandboxed page, or a page opened from a file on your computer, saves while such a tab shows, or showed in the last 60 seconds, a site the session may not act on; and, while a page in those tabs shows more than 200 sites within 60 seconds, every Blob file from a site that session may not act on. Still not stopped: an answer of such a worker that Firefox shows rather than saves, such as a PDF, image or text; one that Firefox saves under another address than that of the tab's load, or after the worker held the load for more than 10 minutes; a file Foxleash could not remove or took more than 5 seconds to remove, which the agent's uploads refuse only for its first 5 seconds; a data: file that a page of such a site builds itself; and a Blob file such a page builds more than 60 seconds after its address last changed, in a frame or window that is removed, closed or sent to another page right then. Other tabs outside the agent's group are not covered. In the tabs of a session you stopped, Foxleash stops every answer that is not a web page, and in the tabs left in the group of a session that ended, also one from a site you allowed only for that session. Foxleash remembers the agent's groups, so their tabs stay covered after Firefox restarts or the extension is updated or reloaded, judged by the sites you allowed always; not covered are the moment before Foxleash has read that list, windows opened from those tabs before, the oldest closed groups once it holds more than 200, and groups made by a version before this one.
- A recipe is saved only by your click on Foxleash's page in Firefox, after you read it; nothing the agent sends can save one, and a saved recipe is read by later agent sessions as your instructions, so read it before saving.
- Allowing a recipe's sites takes your click too, grants them for the session only, never always, and sites on your blocklist or that you refused in the session stay so.
- Allowing the sites an agent asks for takes your click too, on a page that shows only those sites, at most 20, grants them for the session only, never always, and sites on your blocklist or that you refused in the session stay so.
- Tool results mark page content as untrusted, and the agent is told not to follow instructions found in pages.
- When the agent reads a page as text, Foxleash never gives it the values of password fields, of one-time code and card number fields that the page marks as such for autofill, or of text fields that Firefox filled in from your saved logins, addresses or cards, until you edit them, only whether they are filled: Firefox fills saved passwords into login pages when they load, and a page you approved could otherwise hand yours to the agent. When a click or Enter by the agent would send a form with GET, which puts the form's values in the page's address, while the form would send the value of such a field, Foxleash cancels the submission and refuses the action, unless the page's own script sends the form; a form you send yourself with GET still puts its values, these included, in the page's address, which the agent sees. The text of a network response the agent reads, and a file it downloads, can still contain such a value when the site sends it back. A password field that the page turns into another kind of field stays protected only if the agent read the page, took a screenshot of it or acted in it while it was still a password field, and a text field that the page puts in its place shows its value. A text field Firefox filled in shows its value again once Firefox no longer highlights it as filled in: after you edit it; after the page's own scripts report a change to it or go back or forward; after the page reloads itself, with its own scripts or without them; after you duplicate its tab, in the new tab; after you reopen its tab after closing it; after the agent goes back or forward and the page delays that by more than a second; after the agent goes back or forward to a page that a form sent with POST, to a page that takes more than 30 seconds to arrive, to a page whose script stops Foxleash's load of its address, to a page whose server takes more than 20 seconds to answer that load, until it answers, to a page whose server answers that load with no page, such as a 204 No Content answer, to a page whose address has a fragment (a part after #), which the page can give itself, and that holds a frame a form sent with POST, sends a form with POST itself or from a frame before Foxleash loads it again, or does not finish loading within 30 seconds, or to a page on a site you had not approved and then approve; in a frame, after the agent goes back or forward and only that frame changes; after a tab that was unloaded, by you or by Firefox to save memory, is loaded again; and after Firefox restores your windows and tabs when it starts again. Possibly also after you reopen a window you closed; after the agent goes back or forward and Firefox delays telling Foxleash about the page's request by more than a second, or the computer's clock is set back meanwhile; after the agent goes back or forward to a page that starts another load after it arrived, if Firefox tells Foxleash about that load before the page's arrival or within the same millisecond, or from a page that starts another load while the agent leaves it; after the agent goes back or forward to a page whose server answers Foxleash's load of its address with a download; and to another tool call that reads the page while the agent goes back or forward to it. Screenshots hide the text of the same fields, also in frames from other sites, with a style sheet Foxleash adds to each frame while it takes the screenshot; if a frame does not take that style sheet, Foxleash takes no screenshot, unless that frame shows Firefox's error page for a page that could not be loaded or does not allow being shown in a frame, or is a frame of another add-on, such as a password manager's menu, or lies inside one. While it takes a screenshot of a page with such a frame, Foxleash hides that frame and every other frame of the page or frame that holds it, so none of their content is in the screenshot. In a frame, a password field that the frame turns into another kind of field shows its text in screenshots, also when the agent read the page, took a screenshot of it or acted in it while it was a password field.
- When the agent reads a page's network requests, Foxleash never gives it the values a request sent, such as what a login form sent, only the names of the fields, the kind of each value, such as text or a number, and whether each is filled. A form sent with GET puts its values in the page's address instead, and a page's script can put them in the address of a request it makes, both of which the agent sees; Foxleash refuses a click or Enter by the agent that would send a protected field's value in a form sent with GET, but not a form you send yourself or that the page's own script sends. The text of a response the agent reads can still contain what a request sent when the site sends it back.
- When the agent asks for them, Foxleash gives it the text of the responses to a page's fetch and XMLHttpRequest requests, which it keeps only for requests to sites you approved that are not on the blocklist, whichever frame made them, and only for text content, cut to 32,768 characters, with access, refresh and ID tokens and JWTs redacted as a best effort. Foxleash passes every byte of each response on to the page unchanged and never changes a request; the only thing it stops is a page or frame load in an agent's tabs, or in a window opened from them, whose answer is not a web page, as described above. A file the agent downloads is not redacted.

Foxleash asks before it opens a page on a site you have not approved, and it refuses clicks on links and form buttons that lead to another site or out of the browser, such as to an email address. These checks cover where the tab goes, not what a page on an approved site loads or sends: they make it harder for a fooled agent to send what it read to another site by putting it in an address, but they do not stop it. Going back or forward in a tab's history can return to a page on a site you have not approved, and a page on an approved site can redirect, including through an address the agent chose, or send the tab to another site with its own scripts, for example after a click, before Foxleash can ask. In both cases the agent sees only that site's address, and when that site's answer is anything other than a web page, Foxleash stops the load as described above, after the request has reached that site. When an address the agent opens or downloads answers with a redirect to another site, Firefox sends that site all your cookies for it, including those that a link from another site would not carry. A page on an approved site can also load an address on another site that the agent gave it, for example one typed into a search field, while the tab stays on the approved site, such as by showing that address as an image; that site then gets the address with whatever the agent put in it, and Foxleash does not ask. A page's own scripts can also open an email address. Your agent's own permission settings still apply on top of this, but do not rely on them alone. If your agent can also run programs on your computer, for example with its prompts for commands turned off, it can talk to the native host directly instead of through the MCP server. It then gets a new session of its own, which can use every site you allowed always without asking you and which a stop of another session does not reach, and the checks the MCP server makes, such as the allowed upload folders, the refusal of key files and the untrusted marking, do not apply to it. For everything that reaches Firefox through Foxleash, this extension still enforces site approval, the blocklist, the hiding of tabs on other sites and of the values of protected fields such as passwords, the refusal of clicks that lead to another site and the download rules; no add-on can stop a program that changes your Firefox profile or presses keys on your desktop. Revoking the sites you allowed always and stopping its sessions makes such an agent ask you before it opens a site, and disabling Foxleash in Firefox's add-ons manager cuts it off from Foxleash while the add-on stays disabled. Avoid using Foxleash on sites where a mistake is costly (banking, health records, admin panels with destructive actions), and stay nearby while it works.

Firefox gives extensions no way to produce real user input, so all clicks and keystrokes are simulated. Actions that need a real user gesture (writing to the clipboard, entering fullscreen, opening a file picker, and opening pop-up windows and new tabs unless you allow pop-ups for the site) do not work, and neither do sites that ignore simulated events.

Foxleash runs on Linux only, with Firefox desktop 153 or later. It does not work on Firefox for Android. It does not run in Firefox's private windows, so the agent never sees or acts in them, and it does not work at all when Firefox is set to never remember history, which makes every window private.

About the name: the agent works in your Firefox on a leash that you hold, and a leash is also an old collective noun for foxes, as in a leash of foxes.

What the agent asks for goes from the extension to the Foxleash program on your computer and from there to the agent, which may send it on to its model provider. For a tab in the agent's group on a site you approved, the agent gets its URL and title. For any other tab in its group it gets only the site's address (scheme, host and port), with no path, query or title, and for a local file or another page that is not a website, only the kind of address, such as file:. Apart from what the agent opens, downloads, types, uploads and submits in web pages on your behalf, Foxleash itself sends nothing anywhere else.

## Permissions

Why Foxleash requests each permission:

- nativeMessaging: talks to the Foxleash program on this computer, which relays to and from the AI agent.
- tabs: reads the URL and title of the agent's tabs, so the agent can list them and see where each ends up.
- tabGroups: keeps each agent session's tabs in its own orange Foxleash tab group, and acts only on tabs in it.
- scripting: runs its bundled scripts in the agent's tabs to read pages, click, type, fill in forms, record console messages and hand an uploaded file to a page, and during a screenshot adds a style sheet hiding protected fields' text. It never runs code received from outside the extension.
- webRequest: lets the agent read the network requests of its tabs, with the Cookie, Set-Cookie, Authorization, Proxy-Authorization and request Content-Length headers redacted and request bodies reduced to their structure, never values, and the text of their fetch and XHR responses. It passes those on unchanged and never changes a request.
- webRequestBlocking: Firefox lets an extension read a response only for a request its blocking listener saw, so each recorded tab's fetch and XHR requests get one, which returns at once. Once an agent session ran or an agent's group was open, a second cancels a page or frame load in an agent's tabs or a window opened from them whose answer, from a site not approved or blocked, is not a web page.
- webRequestFilterResponse: reads the text of fetch and XHR responses, only from approved, not blocklisted sites, capped, with sign-in tokens redacted as a best effort.
- webNavigation: says when a navigation in the agent's tabs ends, lists a page's frames for screenshots, notes which show an error page, starts recording console messages and requests when an approved page loads or access to it begins, and ties windows opened from the agent's tabs to their session.
- downloads: saves a file the agent asks for in the download folder, with no file chooser, never over an existing file, with the user's cookies, only when its address, before and after redirects, is on approved, not blocklisted sites. Cancels, deleting its file, a download that a blocked or unapproved site's service worker or page made in an agent's tab.
- storage: keeps settings, such as approved sites and the blocklist, and the agent's tab groups, so their tabs stay checked after a restart.
- <all_urls>: the user may approve any site, so sites cannot be listed in advance. It is needed to run scripts in pages, see requests and take screenshots. It reads and acts in a page only while it is on a site the user approved with a click, not blocklisted. What it embeds from other sites, blocklisted ones too, can show up in what the agent reads.

Firefox for Android: not supported (no native messaging or tab groups).

The native messaging host is the foxleash program (apps/server/, Node.js 24) from the same repository, private during development: not extension code, not in the source archive. We provide it on request.

## Data collection and handling

Foxleash lets an AI agent on your computer use your Firefox. This describes what data the Foxleash extension handles and where it goes.

When your AI agent asks for it, the extension sends page content and browsing activity to the Foxleash program on your computer, which passes it to the agent. The agent may send it on to the model provider it uses (for a cloud model, the company that runs the model), under that provider's terms, which Foxleash does not control.

What the agent can reach:

- Only tabs in the agent's Foxleash tab group, such as tabs it opened there, tabs you moved into it and tabs that a page in the group opened.
- Page content (page text, form fields, screenshots, console messages and network requests) comes only from what a tab showed or loaded while its page was on a site you approved with a click in the browser. It can include what that page loads or shows from other sites, blocklisted ones included. The agent cannot approve a site.
- The text of network responses comes only from requests to sites you approved that are not on the blocklist, whichever frame of the page made them.
- For a tab on a site you approved, the agent gets its URL and title. For any other tab in the group it gets only the site's address (scheme, host and port), with no path, query or title, and for a local file or another page that is not a website, only the kind of address, such as file:.
- Foxleash asks you before the agent opens a page on a site you have not approved. The extension's settings list each running agent session, with a button that stops it, and the sites you allowed or refused for it, where you can forget those answers. Going back or forward in a tab's history, and a page on an approved site that redirects or, with its own scripts, sends the tab to another site, for example after a click, can still reach a site you have not approved without asking; the agent then sees only that site's address. When that site's answer to a page or frame load in a tab of the agent's group, or in a window opened from one, is anything other than a web page, such as a file Firefox would save, Foxleash stops it, so nothing of it is saved or shown, unless the tab or window is one from before Firefox restarted or the extension was updated or reloaded. When that site's own service worker gives the answer, Foxleash cancels the download Firefox starts and removes its file a moment later, with the exceptions named above, and an answer of such a worker that Firefox shows rather than saves is still shown. When an address the agent opens or downloads answers with a redirect to another site, Firefox sends that site all your cookies for it, including those that a link from another site would not carry. Whatever the agent puts in an address, types or submits in a page goes to that website, and to wherever that page sends it, as it would if you did it yourself.
- A built-in list of common financial and health sites is blocked by default: when the agent asks to open one of them or to reload a tab that shows one, Foxleash refuses before anything is loaded, and it does not read or act in a tab's page while it shows one of them. Such a tab reaches the agent only as its site's address, even if you approved the site. You can edit the list in the extension's settings. The list is short and names mostly sites in the United States, the Nordic countries and the United Kingdom. It cannot name every such site: a site that is not on it is not blocked until you add it.

Foxleash itself sends nothing anywhere else. It has no servers, no accounts, no analytics and no telemetry. The extension talks only to the Foxleash program on your computer and, when the agent downloads a file, to the sites the file's address and its redirects lead to. Apart from those downloads, neither the extension nor the program makes network connections of its own: the program talks to Firefox through native messaging and to the agent through the agent's standard input and output, and its two parts talk to each other through a local socket. Foxleash contains no AI model.

The extension declares these kinds of data to Firefox:

- Website content (websiteContent): page text and structure, form fields, screenshots, console messages, and the network requests a page makes (URLs, methods, resource types, status, timing, errors, headers, and of what each request sent the field names, the kind of each value and whether each is filled, never the values), and the text of the responses to fetch and XMLHttpRequest requests to sites you approved, capped, with sign-in token fields redacted as a best effort.
- Browsing activity (browsingActivity): the URLs and titles of the tabs on sites you approved in the agent's tab group, the site address of its other tabs, and where their navigations end.
- Authentication information (authenticationInfo): declared because the URLs and titles of tabs on sites you approved, network request URLs, headers and body field names, the text of network responses, console messages and page content the agent reads can carry account details, passwords or sign-in tokens, even though the Cookie, Set-Cookie, Authorization and Proxy-Authorization headers are redacted. Other tabs in the group show the agent only their site's address.

When the agent uploads a file, the Foxleash program reads it only from folders you allowed and refuses dotfiles, files named like keys, files that hold a PEM, OpenSSH, PuTTY, PGP or age private key, and files saved or changed in the last 5 seconds. The extension hands it to the page's file field, or drops it where the page takes dropped files. The page then sends it to that site as a manual upload would. An agent that can also run programs on your computer can hand the extension a file itself, from any folder, without these checks.

When the agent asks to download a file, the extension requests it from the site with all your cookies for that site, as a request from that site's own page would, and saves it in your Firefox download folder on this computer under the name the agent gives, never over an existing file. It saves the file only when the address the agent gave, and the address the file comes from after any redirects, are on sites you approved and not on the blocklist. On the way, a redirect can make Firefox request an address on a site you have not approved or on the blocklist, also with all your cookies for that site, including those that a link from another site would not carry; no file from such a site is saved. The agent gets the file's path and size, and can read the file from there with its own tools. The download shows in Firefox's downloads panel and history. Firefox itself also saves a file that a page or frame in the agent's tabs loads, for example after the agent's click on a link to a file: one from a site you approved is saved as from any page, and Foxleash stops one from a site you have not approved or that is on the blocklist, with the exceptions named above.

When the agent asks to save a screenshot, the Foxleash program on your computer writes it as a PNG file in the folder the agent works in, never outside that folder and never over an existing file. The file holds what the page showed, with the text hidden in password fields, in one-time code and card number fields that the page marks as such for autofill, and in text fields that Firefox filled in from your saved logins, addresses or cards, until you edit them.

The extension keeps your settings, such as the sites you approved and the blocklist, and the recipes you write (a task's steps with the sites it uses), in its local storage in your Firefox profile on this computer, which Firefox does not sync. The extension's settings page, in the Firefox add-ons manager, lists the sites you allowed always and lets you revoke each one, lets you edit the blocklist, and lets you write, edit and delete recipes. It also lists each running agent session with a button that stops it, the sites you allowed or refused for each session and the prompts you closed without an answer, and lets you forget each of those answers. Foxleash keeps these session answers only in memory, never in storage, until the session ends. The agent can also propose a recipe. The extension then opens a page in the agent's tab group that shows the proposed name, description, sites and steps, and, when you have a recipe with that name, your saved version and the changes to its steps; the recipe is stored only when you click Save on that page. When the agent asks, the extension gives it your recipes: their names, descriptions, sites and steps. The agent can also ask you to allow a saved recipe's sites for its session. The extension then opens a page in the agent's tab group that lists them, the sites are allowed for that session only when you click Allow there, and the settings page lists them with the session's other answers. The agent can also ask you to allow, for its session, the sites a task needs. The extension then opens a page in the agent's tab group that lists them, the sites are allowed for that session only when you click Allow there, and the settings page lists them with the session's other answers. A recipe is text you wrote or approved for the agent, kept on this computer and handed only to your own agent program when it asks, so the add-on declares no further data collection category for it.

## Compatibility

Foxleash works on Firefox desktop 153 or later (`gecko.strict_min_version` `153.0`), on Linux:
the local program runs on Linux only.

It does not work on Firefox for Android. Firefox for Android has no `nativeMessaging` or
`tabGroups` API, and there is no local Foxleash program for the extension to talk to.

The manifest declares `"incognito": "not_allowed"`, so Firefox never runs the extension in
private windows, whatever an enterprise policy says, and the add-ons manager offers no switch
for it. When a user granted an earlier version access to private windows, Firefox removes that
permission once the extension starts as a version that declares the key.

The manifest has no `gecko_android` key, so AMO records each version for Firefox desktop
only. That is what each submission requests: `"compatibility": ["firefox"]` in the version
object of the AMO v5 API, which `web-ext sign` passes through `--amo-metadata`. It is also
AMO's default for an API submission that names no compatibility.

addons-linter still checks `data_collection_permissions` against Firefox for Android. When
`gecko_android` is absent it falls back to `gecko.strict_min_version` (153) for its Firefox
for Android checks, and Firefox for Android supports the key from 142, so the linter reports
no warning. The extension build fails on any linter error or warning.

Adding `gecko_android` to quiet the linter would make AMO mark every version compatible with
Firefox for Android. AMO takes Firefox for Android compatibility from that key. This is in
AMO's server code (addons-server, `Version.from_upload` and the version `compatibility`
field of its API), not in the public API documentation. A version whose manifest has the key
is marked compatible with Firefox for Android from its `strict_min_version`, even when the
submission requests Firefox only, and AMO's API refuses to remove that mark afterwards.
